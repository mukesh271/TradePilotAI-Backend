# TradePilot AI — Project Details

This document provides an in-depth technical overview of the TradePilot AI solution for developers and contributors.

## 1. Purpose

TradePilot is a trading-assistance platform that:

1. Tracks financial instruments (stocks/indices) on exchanges such as NSE.
2. Runs configurable **strategies** that evaluate market conditions and emit **signals** (buy/sell recommendations with entry price, stop-loss, target, and risk/reward ratio).
3. Calculates **risk-adjusted position sizes** so that no single trade risks more than a configured percentage of trading capital.
4. Allows **paper trading** — simulating trade execution against signals to validate strategies without financial risk.
5. Tracks **strategy performance** over time (win rate, P&L, etc.).
6. Ingests **news** and scores its sentiment/relevance to instruments.
7. Runs a background **market scanner** worker that periodically looks for new trading opportunities.

## 2. Architecture

The solution follows a layered / clean-architecture style split across five projects:

### TradePilot.Domain
Contains only plain C# entity classes and enums — no external dependencies. This is the core model shared by every other project.

### TradePilot.Infrastructure
- `TradePilotDbContext` — EF Core database context mapping all domain entities to SQL Server tables.
- `Migrations/` — EF Core code-first migrations (`InitialCreate`, `ExpandedModelWithTradeResultAndNews`).
- `DbInitializer` — seeds the database with initial/sample data.

### TradePilot.Api
The ASP.NET Core Web API (presentation layer):
- `Controllers/` — REST endpoints (see section 4).
- `DTOs/` — request/response data transfer objects, decoupled from domain entities.
- `Services/RiskManagementService.cs` — position-sizing/risk calculation logic.
- `Middleware/GlobalExceptionHandlingMiddleware.cs` — centralized exception handling for all requests.
- `Program.cs` — application bootstrap: DI registration, EF Core SQL Server configuration, Swagger, logging, database seeding.

### TradePilot.Worker
A standalone background service (`Microsoft.Extensions.Hosting`):
- `MarketScannerWorker` — a `BackgroundService` that runs a scan loop every 30 seconds (MVP: logs only; intended to later fetch market data, evaluate indicators, and generate signals).
- `Abstractions/IMarketDataProvider` — abstraction point for plugging in real market data sources (e.g., broker APIs).

### TradePilot.Tests
Test project for unit/integration coverage of the above layers.

## 3. Domain Model

| Entity | Key Fields | Description |
|--------|-----------|-------------|
| `Instrument` | `Symbol`, `Exchange`, `Type`, `IsActive` | A tradable security (stock, index, etc.) |
| `Strategy` | `Name`, `Description`, `IsActive` | A named trading strategy that can be enabled/disabled |
| `Signal` | `InstrumentId`, `StrategyId`, `Direction`, `SignalScore`, `EntryPrice`, `StopLoss`, `Target`, `RiskRewardRatio`, `TimeFrame`, `Explanation`, `Status`, `ExpiresAtUtc` | A trade recommendation generated by a strategy for an instrument |
| `SignalCondition` | (linked to `Signal`) | Individual condition(s) that contributed to a signal being triggered |
| `PaperTrade` | `SignalId`, `EntryPrice`, `ExitPrice`, `Quantity`, `ProfitLoss`, `Status`, `TradeResult` | A simulated trade opened against a signal |
| `TradeResult` | — | Outcome classification of a closed paper trade (e.g., win/loss) |
| `StrategyPerformance` | (linked to `Strategy`) | Aggregated/historical performance metrics per strategy |
| `RiskSettings` | `TradingCapital`, `RiskPerTradePercent`, `MaximumDailyLossPercent`, `MinimumSignalScore`, `PaperTradingEnabled` | Global risk configuration used to size positions and filter signals |
| `News` | `Title`, `Source`, `Url`, `Summary`, `Sentiment`, `RelevanceScore`, `PublishedAtUtc` | A news item relevant to instruments, with sentiment scoring |

### Enums
- `InstrumentType` — classifies an instrument (e.g., Equity, Index)
- `SignalStatus` — lifecycle state of a signal (e.g., Active, Expired, Triggered)
- `TradeStatus` — lifecycle state of a paper trade (e.g., Open, Closed)
- `NewsSentiment` — Positive / Negative / Neutral classification

### Default Risk Settings
```
TradingCapital            = 20,000
RiskPerTradePercent       = 1%
MaximumDailyLossPercent   = 2%
MinimumSignalScore        = 75
PaperTradingEnabled       = true
```

## 4. API Endpoints (by Controller)

| Controller | Responsibility |
|------------|----------------|
| `InstrumentsController` | List/create/update instruments; toggle active status |
| `StrategiesController` | List/create/update strategies |
| `SignalsController` | Query signals, filter by instrument/strategy/status, view signal conditions |

| `PerformanceController` | Retrieve aggregated strategy performance statistics |

All controllers return responses wrapped in a consistent `ApiResponse<T>` DTO envelope.

## 5. Risk Management Logic

`RiskManagementService.CalculatePositionRisk(capital, riskPercent, entryPrice, stopLoss)`:

1. Validates inputs (capital > 0, 0 < riskPercent ≤ 100, prices > 0, entry ≠ stop-loss).
2. `MaximumRiskAmount = capital * (riskPercent / 100)`
3. `RiskPerUnit = |entryPrice - stopLoss|`
4. `SuggestedQuantity = floor(MaximumRiskAmount / RiskPerUnit)`
5. `PotentialLoss = SuggestedQuantity * RiskPerUnit`

This ensures every suggested trade size respects the configured maximum capital-at-risk.

## 6. Background Worker

`MarketScannerWorker` (in `TradePilot.Worker`) is a `BackgroundService` that:
- Runs continuously while the host is alive.
- Executes a scan cycle every 30 seconds via `PerformMarketScanAsync`.
- Currently a stub (MVP-1): logs scan cycle start/end only.
- Designed to be extended to: fetch instruments → get market data via `IMarketDataProvider` → evaluate technical indicators → generate `Signal` entities → persist them.
- Catches and logs exceptions per cycle so a single failure doesn't stop the scanner.

## 7. Database

- EF Core 10 with SQL Server provider (`Microsoft.EntityFrameworkCore.SqlServer`).
- Code-first migrations stored in `TradePilot.Infrastructure/Migrations`.
- `DbInitializer` seeds baseline data (e.g., default risk settings, sample instruments) on startup.
- Connection string key: `ConnectionStrings:TradePilotDb` (configured in `appsettings.json` / `appsettings.Development.json`).
- Resilient connections via `EnableRetryOnFailure` (5 retries, up to 30s delay).

## 8. Cross-Cutting Concerns

- **Global exception handling** — `GlobalExceptionHandlingMiddleware` catches unhandled exceptions and returns a consistent error response.
- **Logging** — Console and Debug logging providers registered in `Program.cs`.
- **API Documentation** — Swashbuckle generates OpenAPI spec + Swagger UI (development only), served at the application root.
